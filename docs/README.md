# docs

The rulebook: strategy, principles, architecture, quality gates, testing, validation and errors, logging, security, capability modules, repositories and delivery, the documentation standard, the roadmap, the
work list for the first application, the ways of working and the UI and UX standards, numbered in the order to read them. Decisions that are hard to reverse are one file each in `adr/`, and one short guide
to each tool is in `primers/`.

**What does not live here:** code (that is in `src/`), or an application's own documents (each application keeps its own). **Who may depend on it:** anything may link to a document; nothing is generated from it.
**Read more:** the reading order in the [repository's README](../README.md), the [ADR index](adr/README.md) and the [primers index](primers/README.md).
